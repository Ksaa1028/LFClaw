# 经营分析规则

## 销售与客流

按经营漏斗判断：客流 → 进店率 → 深逛率 → 成交率 → 客单价 → 连带率 → 会员复购。

销售下降时依次判断：

1. 客流不足还是转化不足。
2. 订单数下降还是客单价下降。
3. 单品牌拖累还是楼层整体问题。
4. 活动引流不足还是现场承接不足。
5. 导购执行还是商品、陈列、服务问题。
6. 是否涉及招商结构、客服体验、物业现场或数据口径。
7. 是否存在保底、收益、费用或结算风险。

没有某个漏斗指标时，明确标注“数据缺口”，不要用相邻指标替代。

## 数据校验

输出结论前执行以下一致性检查：

1. 用销售额 ÷ 目标复核完成率，允许因展示四舍五入产生小误差。
2. 完成率低于 100% 不得写“超额完成”；高于或等于 100% 才标记达标/超额。
3. 表格、核心结论、异常分析和责任动作中的达标状态必须一致。
4. 只取得同比时不得写“同比、环比双降”；只陈述实际返回的比较口径。
5. 订单数、商品数、客流或金额出现数量级异常时，先标记“疑似口径或数据异常”，不得直接推导客单价、转化率或经营原因。
6. 不用销售额 ÷ 销售订单数自行声称客单价异常，除非确认订单单位、销售额单位、租赁/联营数据口径一致。
7. 合计数优先使用工具返回值；自行求和时说明可能存在分项四舍五入误差。
8. 原因必须有数据或知识资料支持。只有现象没有证据时写成“待验证假设”，并给出下一步查询。
9. 输出前逐项比对核心结论、明细表、异常清单、责任归口和管理动作；同一对象的达标状态、变化方向和缺口必须一致。
10. 组织和部门名称必须沿用飞书人力资料中的正式名称。例如使用“营销部”，不自行替换为“市场部”。
11. 实际低于目标只能证明存在目标缺口，不能据此断言“目标虚高”“目标与经营能力脱节”或建议下调目标；必须查询目标制定依据、审批口径、历史趋势和经营计划后再判断。
12. 只有销售额和同比数据时，不得写“量价齐跌”；判断量、价分别变化必须取得可比订单量/销量及客单价/件单价数据。
13. 楼层业态构成、品牌撤柜、季节性、活动吸引力和促销影响必须有兜知数据或飞书资料支撑；否则只能列为待验证假设，不得写成原因。
14. 月度目标制定、分解和审批的责任部门必须查询制度与职责资料确认，不默认归给营运部或营销部。

## 品牌经营模式

- 联营：销售、扣率、毛利、坪效、转化、会员和评价。
- 租赁：租金与结算稳定性、客流贡献、服务和形象。
- 自营：销售、毛利、库存、人效和损耗。

兜知当前店铺工具的经营方式明确支持联营、租赁；遇到自营时先确认数据口径和可用字段。

## 招商与方案

判断项目定位、商圈价值、客群匹配、楼层业态、合同租金、保底收益及调改/续签/淘汰价值。

资料不完整时仍给初版方案，同时显式列出假设与待补数据。缺少 CAD 或铺位表时先输出文字分区和落位逻辑，并要求补充铺位号、面积、现品牌、入口、扶梯、电梯、卫生间、冷热区和主力店位置。

## 财务

结合经营表现和品牌结算分别判断收益结构、费用、结算额、应付账款、保底风险和需要采取的营运帮扶、招商调改或合同复盘。

不得把销售增长直接等同于利润改善。兜知结算工具未直接返回净收益率或利润时，不编造指标；需要公式或财务制度支持后再计算。

## 责任归口

1. 先判断第一责任业务部门。
2. 查询职责边界、岗位和组织关系。
3. 尽量落到离问题最近的直接责任岗位和人员。
4. 区分第一责任部门与协同部门。
5. 写明判断依据，不把相关性表述为已证实责任。

责任归口至少包含：第一责任部门、具体责任人/岗位、直属上级、协同部门、判断依据、通知建议。

楼层经营责任优先查询飞书《部长级责任人速查表》，再用《关键岗位名单》交叉核对。普通楼层异常默认定位部长级/区域经理责任链，不擅自下钻到导购和店长；自营品牌使用自营专属责任链。

责任人命中后，输出“业务对象—第一责任人—直属上级—分管领导—协同人员/部门”的实际责任链。若两份资料中的岗位或姓名冲突，明确列出冲突及资料更新时间，不擅自择一；只有完成两级查询仍无结果时才写“待确认”。

若回答已包含“责任归口”栏目，必须同时满足：已实际读取《部长级责任人速查表》，且已读取《关键岗位名单》完成交叉核对。工具不可用或未授权时，删除虚假的责任人结论，改为在开头报告能力阻断，并提示为智能体绑定 `feishu-cli` 或完成飞书用户授权。

## 干部测评

结合个人测评、岗位资料和人才观资料，转化为管理判断，不堆砌原始分数。输出能力画像、优势、风险、适合场景、所需约束、上级指导和管理动作。

措辞保持客观克制。使用“需要带教”“需要上级复核”“稳定性待验证”“需要过程约束”，避免给个人贴永久性负面标签。

## 任务拆解

只有用户明确要求任务确认单、拆任务、责任分工、执行清单或整改步骤时进入拆解。

用户只要求方案、规划、策略或建议时，先给初版方案，不直接变成任务单。

动作拆到约 30–120 分钟可完成，每步写清动作、产出物、留痕位置、验收方式和截止时间。明确唯一责任人、协作者与依赖项。

## 后续处理层级

- 日常跟进：单日波动、轻微异常、局部风险。
- 专项复盘：问题已暴露，需要短期复盘与动作。
- 管理升级：连续异常、跨部门卡点、目标明显偏离、整改无效或收益风险扩大。
- 风险直报：安全、消防、重大客诉、舆情、法律、重大系统故障或重大资金风险。
